# Plan 01 — Multi-Provider Setup Wizard

## Goal
Extend the setup wizard to support multiple provider groups (name, base URL, keys) in one atomic flow.

## Tasks

### Task 1 — Backend: Accept `groups` array in `SetupReq`
**Files:** `src/settings.rs`, `src/config.rs`
- Add optional `groups` field to `SetupReq`: `Vec<SetupGroup>` with `{name, base_url, keys: Vec<SetupKey>}`
- `SetupGroup`: `{name: String, base_url: String, keys: Vec<SetupKey>}`
- In `setup_submit`: when `groups` is non-empty, create endpoint groups instead of using the single `upstream` path
- Each group becomes an `EndpointGroup { name, base_url, keys }` in the config
- When `groups` is empty (legacy), fall back to existing single-group behavior
- Preserve `NoScriptSetupForm` — noscript always submits single-group

### Task 2 — Backend: Atomic multi-group claim
**Files:** `src/settings.rs`
- In `setup_submit`, when `groups` is present:
  - Create all endpoint groups atomically under the store lock
  - If any group has zero valid keys, reject the entire claim
  - Rollback on failure: no partial endpoint groups remain
- Validate each group has at least one key
- Validate group names are unique

### Task 3 — Frontend: Group card UI in step 2
**Files:** `src/web/setup.html`, `src/web/setup.js`
- Replace single key-list with group cards container
- Each group card: name input, base URL input (pre-filled from previous group or default), key list, add-key button
- "Add provider group" button below the cards
- Remove group button (×) on each card except the last
- Default first group name: "Provider 1" (i18n key)

### Task 4 — Frontend: Group state machine
**Files:** `src/web/setup.js`
- Replace flat `keys` array with `groups` array: `[{name, base_url, keys: [{key, rpm, models}]}]`
- Active group tracking (which card is focused)
- Add/remove group operations
- Key validation hits each group's own base_url
- "Continue" enabled only when all groups have at least one valid key

### Task 5 — Frontend: Review step shows all groups
**Files:** `src/web/setup.js`
- Step 3 review shows each group as a card: name, base URL, key count, total RPM
- Summary line: "X groups, Y keys total"
- `create_client_key` only sent for first group

### Task 6 — Frontend: Noscript fallback + hint
**Files:** `src/web/setup.html`
- Existing noscript fallback fields stay unchanged (single key + base URL)
- Add noscript-only hint text: "For multiple providers, enable JavaScript"
- Form still submits valid single-group payload via `NoScriptSetupForm`

### Task 7 — i18n: New catalog keys
**Files:** `src/web/locales/en-US.json`
- `setup.step2.group_name`: "Provider name"
- `setup.step2.group_base_url`: "Upstream base URL"
- `setup.step2.add_group`: "Add another provider"
- `setup.step2.remove_group`: "Remove"
- `setup.step2.group_hint`: "For multiple providers, enable JavaScript"
- `setup.step3.review.group`: "Provider {name}"
- `setup.step3.review.groups_summary`: "{count} providers, {keys} keys total"

### Task 8 — Verification
**Files:** scripts/render_check.js
- Update render_check to test: add key to group, add second group, submit multi-group
- Verify noscript fallback still submits valid single-group
- `cargo test` passes
- `cargo fmt --check` passes
