     5→     5→     5→# open-proxy
     6→     6→     6→
     7→     7→     7→**A tiny, multi-provider, rate-limit-aware OpenAI-compatible proxy. One proxy, every provider, zero 429s.**
     8→     8→     8→Add API keys from NVIDIA NIM, OpenRouter, TokenRouter, OpenAI, or any OpenAI-compatible API — open-proxy merges them into a single pool, obeys every upstream's speed limit, and keeps your clients running.

    21→    21→    21→
    22→    22→    22→Every upstream provider has its own rate limits — typically 40 requests per minute per API key. When a client (OpenCode, Codex, n8n, or anything that speaks the OpenAI API) hits that limit, the upstream returns a 429 and most clients simply abort the task. open-proxy sits in between and makes the limit invisible:
    23→    23→    23→
    24→    24→    24→```
    25→    25→    25→OpenCode ─┐
    26→    26→    26→Codex     ├──► open-proxy ──┬─► integrate.api.nvidia.com   (NIM free tier)
    27→    27→    27→n8n       ┘    │             ├─► openrouter.ai/api/v1       (OpenRouter)
    28→    28→    28→               │             ├─► api.tokenrouter.com         (TokenRouter)
    29→    29→    29→               │             └─► api.openai.com/v1           (OpenAI)
    30→    30→    30→               │
    31→    31→    31→               ├─ paces requests per key (sliding window, respects each upstream's limit)
    32→    32→    32→               ├─ load-balances across all your keys and providers
    33→    33→    33→               ├─ pins each conversation to one key (prefix-cache affinity)
    34→    34→    34→               ├─ rides out 429/5xx with retries + Retry-After
    35→    35→    35→               ├─ adapts to per-model worker-concurrency ceilings
    36→    36→    36→               ├─ keeps client connections alive with SSE heartbeats
    37→    37→    37→               ├─ answers /v1/models from cache (catalog polls cost nothing)
    38→    38→    38→               └─ dashboard + Prometheus metrics for everything above
    39→    39→    39→```
    40→    40→    40→
    41→    41→    41→The more keys you add, the higher your combined throughput: 3 NIM keys (120 RPM) + 5 OpenRouter keys (200 RPM) = **320 RPM** total, automatically distributed. Each key holds to its own upstream's limit; the proxy just makes agents patient enough to live within the budget. Load-tested to prove it: 100 concurrent clients, zero upstream rate violations.

    82→    82→    82→## Client recipes
    83→    83→    83→
    84→    84→    84→Model IDs pass through verbatim — use any model ID your provider supports (or `curl localhost:8000/v1/models` to see the merged catalog).    135→   135→   135→
   136→   136→   136→For benchmarks or bounded jobs, add
   137→   137→   137→`X-Nim-Proxy-Deadline-Ms: <milliseconds>`. This is an absolute wall-clock
   138→   138→   138→deadline across proxy queueing, retries, and generation; heartbeats and output
   139→   139→   139→chunks do not reset it. Buffered requests expire with HTTP 504 and error code
   140→   140→   140→`deadline_exceeded`. Streaming requests have already committed HTTP 200, so
   141→   141→   141→they receive the same code in a terminal SSE error event. Requests without the
   142→   142→   142→header retain the proxy's normal patient behavior.

   151→   151→   151→sampling, where models truncate, and how much "thinking" a reasoning model
   152→   152→   152→burns — all from counts and sizes, never message content.

   195→   195→   195→## How it works
   196→   196→   196→
   197→   197→   197→- **One rate window per key.** Each API key gets an exact sliding-window limiter (configurable per key, defaulting to 40 requests per rolling 60 s — matching common upstream limits, not a burstable token bucket — plus a 1 s jitter margin so boundary-timed requests can't land inside the upstream's window).
   198→   198→   198→- **One queue for all clients.** Any number of clients share the key pool through a global FIFO dispatcher: slots are granted strictly in arrival order, no client can starve another, and a client that disconnects while queued returns its slot.
   199→   199→   199→- **Sticky conversations, spread bursts.** Each conversation prefers the same key every turn, keeping any server-side prefix cache warm. When that key is full the request spills to the least-loaded ready key — the API is stateless, so crossing keys is always safe, just potentially a cold cache.
   200→   200→   200→- **Heartbeats instead of failures.** For streaming requests the proxy commits to `200 text/event-stream` immediately and emits SSE comment lines (`: heartbeat` — ignored by every OpenAI client) while it waits for a slot or rides out upstream 429/500/502/503/504 with `Retry-After` honored and instant failover between keys. Streams that stall mid-generation are cut after the `stream_idle` limit.
   201→   201→   201→- **Optional absolute deadlines.** `X-Nim-Proxy-Deadline-Ms` bounds the whole request independently of heartbeats or socket activity. Expiry cancels queue/retry/upstream work and releases its key, model, and in-flight ownership.
   202→   202→   202→- **Model-pressure aware.** Some providers cap per-model worker concurrency independently of the per-key rate limit; the proxy detects that specific exhaustion, backs off the affected *model* adaptively (never wasting healthy key capacity on failover), and surfaces it on the dashboard — see [architecture: governor](knowledge/architecture/governor.md).
   203→   203→   203→- **Pass-through with one exception.** Bodies are forwarded untouched, except: streaming chat requests get `stream_options: {"include_usage": true}` injected so token accounting is exact rather than estimated. If a model rejects the field, the proxy retries untouched and never injects for that model again. `strict_passthrough` in Settings disables injection entirely.
   204→   204→   204→- **Local answers where possible.** `GET /v1/models` is cached (10 min default, single-flight refresh), so client catalog polls don't burn rate budget. With several endpoint groups the catalog fans out (one slot per group that has a key) and merges by model id, minus globally disabled models.

   206→   206→   206→## Configuration
   207→   207→   207→
   208→   208→   208→App-level configuration lives in the dashboard (Settings) and persists to
   209→   209→   209→`DATA_DIR/config.json`. Settings saves apply live; the file is otherwise read
   210→   210→   210→at boot, so manual or automated out-of-band edits require a restart.
   211→   211→   211→Environment variables cover container-level concerns only:
   212→   212→   212→
   213→   213→   213→| Variable | Default | Purpose |
   214→   214→   214→|---|---|---|
   215→   215→   215→| `HOST` / `PORT` | `0.0.0.0` / `8000` | Bind address and port |
   216→   216→   216→| `DATA_DIR` | `data` (`/data` in Docker) | Where the config store and canonical `history-v1.jsonl` live; must be writable (an unwritable dir is a hard boot error) |
   217→   217→   217→| `TRUST_PROXY` | `false` | Trust `X-Forwarded-Proto` and mark the session cookie `Secure` (set behind a TLS-terminating reverse proxy) |
   218→   218→   218→| `RUST_LOG` | `nim_proxy=info` | Log filter |
   219→   219→   219→
   220→   220→   220→Docker Compose also reads `PUBLISH_HOST` from `.env` for the host-side port
   221→   221→   221→publish. It defaults to `127.0.0.1`; set `PUBLISH_HOST=0.0.0.0` only when the
   222→   222→   222→deployment is ready for LAN/public reachability. This is a Compose setting,
   223→   223→   223→not an environment variable consumed by the proxy.
   224→   224→   224→
   225→   225→   225→Everything else is a Settings control: endpoint groups (each an
   226→   226→   226→OpenAI-compatible API with its own base URL, keys, enable toggle, and model
   227→   227→   227→allowlist), upstream API keys (per-key rpm,
   228→   228→   228→enable/disable, ownership, group assignment), model toggles (globally
   229→   229→   229→disabled models are hidden from the merged `/v1/models` catalog and rejected
   230→   230→   230→with `model_disabled` before queueing), the upstream base URL (the primary
   231→   231→   231→group's), client API keys and the API authentication
   232→   232→   232→mode (`keyed`/`open` in stored config), limits (`max_wait`, `heartbeat`,
   233→   233→   233→`stream_idle`, `request_timeout`, `models_ttl`, `max_inflight`,
   234→   234→   234→`strict_passthrough`), default time range, history retention, availability SLO,
   235→   235→   235→model limits, and users & roles.
   236→   236→   236→
   237→   237→   237→Requests route by model name: a model pinned in a group's allowlist is served
   238→   238→   238→only by that group; any other model falls back to the groups with an empty
   239→   239→   239→allowlist (catch-alls). A model no enabled group carries is a `404
   240→   240→   240→model_not_found`, not a wait-until-timeout.

   242→   242→   242→## Security & deployment
   243→   243→   243→
   244→   244→   244→The proxy **fails closed**. Before setup, the data plane is closed (`/v1` → `503 setup_required`) and browsers are sent to the wizard. After setup, the dashboard and all observability **always** require a logged-in user; `/v1` is either **API key required** (`keyed`) or **Open (no authentication)** (`open`). Credentials live in the config store on the data volume (`config.json`, mode 0600) — not in env vars.
   245→   245→   245→
   246→   246→   246→### Users & roles
   247→   247→   247→
   248→   248→   248→The wizard creates the **superuser** — an admin that can never be deleted (so the last admin can't vanish). From Settings → Users, admins add more users:
   249→   249→   249→
   250→   250→   250→- **superuser** — an admin; the one account that can't be deleted, and it always owns ≥1 enabled API key (the pool floor).
   251→   251→   251→- **admin** — server settings + user management.
   252→   252→   252→- **user** — own account, own client API keys, own upstream API keys. Sees every dashboard tab (identical for all roles) but only their own key rows.
   253→   253→   253→
   254→   254→   254→That last role is the shared-pool model: a friend adds their API key to the pool and mints their own client key; nobody else — not even an admin — can ever see either value.
   255→   255→   255→
   256→   256→   256→Login is username + password → a signed, HttpOnly, SameSite=Strict session cookie. Changing or resetting a password logs that user's other sessions out instantly; deleting a user kills their sessions, pulls their API keys from the pool, and revokes their client keys. Passwords are PBKDF2-HMAC-SHA256 (600k iterations). Forgot a password? Any admin resets it (except the superuser's — that one only rotates via its own Account page). Locked out entirely? Stop the container, empty the `"users"` array in `config.json` on the volume, restart — the wizard re-creates the superuser and keys/settings survive.
   257→   257→   257→
   258→   258→   258→### `/v1` API authentication
   259→   259→   259→
   260→   260→   260→- **API key required** (`keyed`, default) — clients send `Authorization: Bearer <npk_…>`. Each user mints their own client keys; a key's 128-bit secret is shown **exactly once** (only its SHA-256 digest + last-4 are stored). This mode with zero client keys rejects everything (fail closed). Unknown keys get an OpenAI-style 401; comparison is constant-time.
   261→   261→   261→- **Open (no authentication)** (`open`) — `/v1` is unauthenticated. Only for loopback or a fully private network. This toggle affects **only `/v1`** — the dashboard is never open.
   262→   262→   262→
   263→   263→   263→The compose file publishes `127.0.0.1:8000:8000` by default so a bare
   264→   264→   264→bring-up can't leak. Set `PUBLISH_HOST=0.0.0.0` in `.env` when intentional
   265→   265→   265→LAN/public exposure is protected appropriately.

   280→   280→   280→### The dashboard API
   281→   281→   281→
   282→   282→   282→The routes the dashboard and the setup wizard call are described by
   283→   283→   283→[`openapi.json`](openapi.json) at the repo root — 17 operations covering 15
   284→   284→   284→`/api/*` routes plus the two unauthenticated `/setup` ones. The public
   285→   285→   285→`GET /api/locale-bootstrap` operation and both setup operations explicitly
   286→   286→   286→waive the document-level authentication requirement; the other 14 `/api/*`
   287→   287→   287→operations require operator authentication. The spec is
   288→   288→   288→**generated from the handlers** (`utoipa`) and CI fails on any drift, so it
   289→   289→   289→cannot describe a version of the API that no longer exists. Point any offline
   290→   290→   290→viewer or client generator at it; nothing is served at runtime, which keeps
   291→   291→   291→the Content-Security-Policy strict and the image a single static binary.
   292→   292→   292→
   293→   293→   293→The OpenAI-compatible `/v1` surface is deliberately not in there — that
   294→   294→   294→contract is your upstream provider's, and open-proxy passes it through.

   296→   296→   296→### Deployment patterns
   297→   297→   297→
   298→   298→   298→| Pattern | How |
   299→   299→   299→|---|---|
   300→   300→   300→| **Local self-host** | Keep the default loopback port publish; switch to **Open (no authentication)** in Settings if you don't want client keys. |
   301→   301→   301→| **VPS / bare metal** | A TLS-terminating reverse proxy (nginx/Caddy) in front; keep **API key required**. Set `TRUST_PROXY=true` so the session cookie is marked `Secure`. |
   302→   302→   302→| **PaaS (ECS / Railway / Fly)** | The platform edge terminates TLS. Set `TRUST_PROXY=true`. Complete the wizard as soon as the instance is reachable. |
   303→   303→   303→
   304→   304→   304→**TLS is not built in** — passwords and keys must travel over HTTPS, so terminate TLS at a reverse proxy or platform edge for any exposed deployment. Additional hardening in place: a strict `Content-Security-Policy` and anti-framing/sniffing headers on all responses, a failed-login throttle, and an in-flight cap (`max_inflight`) that sheds floods with a 503.

   306→   306→   306→### Supply chain
   307→   307→   307→
   308→   308→   308→The build and release path is hardened to the OpenSSF baseline (scored weekly by the [Scorecard badge](https://scorecard.dev/viewer/?uri=github.com/miztertea/nim-proxy) above): every GitHub Actions step is SHA-pinned, CI runs **CodeQL** static analysis, workflow linting (`actionlint` + `zizmor`), dependency review, and `cargo-deny` (advisories on every PR plus a weekly audit), and the untrusted-byte parsers are **fuzzed** weekly. Releases are signed with keyless [cosign](https://docs.sigstore.dev/): the multi-arch image carries a signature, SLSA build provenance, and an SPDX SBOM, and the downloadable tarballs + SBOM each ship a `.sigstore.json` bundle you can check with `cosign verify-blob` (the exact command is in every release's notes). Published `v*` tags are protected against retagging.

   310→   310→   310→## Operations
   311→   311→   311→
   312→   312→   312→- **Image**: built `FROM scratch` — a ~5 MB static musl binary with TLS roots compiled in. No shell, no libc, no CA bundle. Runs as a non-root UID with `read_only`, `cap_drop: ALL`, `no-new-privileges`; rootless Docker/Podman compatible.
   313→   313→   313→- **Healthcheck**: the binary doubles as its own probe (`open-proxy --health`); `docker ps` shows `healthy`.
   314→   314→   314→- **Logs**: the ASCII banner + structured startup detail, then one access line per request (`200 alice model /v1/chat/completions (3210 ms)`). ANSI color is TTY-detected, so `docker logs` stays clean.
   315→   315→   315→- **Metrics**: Prometheus exposition at `GET /metrics` (scrapeable by any OTel collector's Prometheus receiver). Full series list below.
   316→   316→   316→- **Shutdown**: SIGTERM and SIGINT both drain gracefully.

   359→   359→   359→
   360→   360→   360→Four layers (unit, end-to-end, load, fuzz), all runnable locally:
   361→   361→   361→
   362→   362→   362→```sh
   363→   363→   363→cargo test          # unit + end-to-end tests (real binary vs a scripted mock upstream)
   364→   364→   364→```
   365→   365→   365→
   366→   366→   366→The e2e suite covers auth (client keys, multi-user login, role and ownership enforcement, the fail-closed setup posture and the wizard), the config store (round-trip across restart, atomic saves, refusal on corrupt/future-version stores), 429 ride-out with key failover, per-model worker-exhaustion governing, Retry-After timing, pacing enforcement (including live pool rebuilds mid-run), conversation affinity, models caching, usage injection, stalled-stream recovery, label-injection sanitizing, security headers, metrics accuracy, history persistence across restart, and SIGTERM.
   367→   367→   367→
   368→   368→   368→Load test — 100 concurrent clients against a mock that *strictly enforces* the upstream's per-key window and counts violations (`--worker-slots` also emits per-model worker-exhaustion errors so the governor is exercised):
   369→   369→   369→
   370→   370→   370→```sh
   371→   371→   371→python3 scripts/mock_nim.py --enforce --rpm 40 --worker-slots 32 --port 9999 &
   372→   372→   372→cargo run --release &     # complete the wizard against http://127.0.0.1:9999
   373→   373→   373→python3 scripts/loadtest.py --clients 100 --requests 3
   374→   374→   374→```
   375→   375→   375→
   376→   376→   376→It exits non-zero on any client-visible failure or a single upstream rate violation, and reports worker exhaustions + peak per-model concurrency.
